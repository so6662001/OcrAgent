## 第一部分：销售流程框架

### 1.1 标准销售七步法

```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 1.潜客开发 │──→│ 2.建立信任 │──→│ 3.需求诊断 │──→│ 4.方案呈现 │
└──────────┘   └──────────┘   └──────────┘   └──────────┘
                                                    │
┌──────────┐   ┌──────────┐   ┌──────────┐         │
│ 7.售后服务 │←──│ 6.成交签约 │←──│ 5.异议处理 │←────────┘
└──────────┘   └──────────┘   └──────────┘
```

| 阶段 | 目标 | 关键动作 | 输出物 |
|------|------|----------|--------|
| 1. 潜客开发 | 找到目标客户 | 画像匹配、渠道触达、初步筛选 | 潜客清单 |
| 2. 建立信任 | 获得客户好感与初步信任 | 破冰寒暄、专业展示、共情倾听 | 关系建立 |
| 3. 需求诊断 | 精准了解客户痛点和诉求 | SPIN提问、现状分析、痛点定位 | 需求分析报告 |
| 4. 方案呈现 | 让客户认可解决方案的价值 | FABE法则、场景演示、案例佐证 | 方案提案 |
| 5. 异议处理 | 消除客户疑虑和反对意见 | LSCPA模型、同理心回应 | 异议记录与回应 |
| 6. 成交签约 | 促成合同签订与付款 | 试探成交、紧迫感塑造、临门一脚 | 合同/订单 |
| 7. 售后服务 | 客户满意与复购转介绍 | 定期回访、增值服务、满意度调查 | 复购/转介绍 |

### 1.3 客户分级管理 (ABCD法)

| 等级 | 特征 | 跟进频率 | 资源投入 |
|------|------|----------|----------|
| **A级 — 热客** | 需求明确、预算到位、决策人对接、近期要成交 | 每天 | 70%精力 |
| **B级 — 温客** | 有需求意向、正在评估、决策流程中 | 每3天 | 20%精力 |
| **C级 — 冷客** | 有潜在需求、未到采购阶段 | 每2周 | 8%精力 |
| **D级 — 储备** | 符合画像但暂无明确需求 | 每月 | 2%精力 |

## 第二部分：客户需求挖掘工具

### 2.1 SPIN提问法

SPIN是四类递进式问题的组合，逐步引导客户认识到问题的严重性并产生改变的紧迫感。

#### S — Situation（现状问题）

> 了解客户当前状况，收集基础信息

| 提问模板 | 示例 |
|----------|------|
| "目前贵公司在XX方面是怎么做的？" | "目前贵公司的采购订单是怎么录入系统的？" |
| "现在使用的XX方案/工具是哪个？" | "现在用的是哪个ERP系统来管理进销存？" |
| "负责这块业务的团队有多少人？" | "录入单据的团队有多少人？每天处理多少单？" |
| "这个流程大概持续多长时间了？" | "手工录入的方式用了多久了？" |

**注意**：现状问题不宜过多（3-5个），太多会让客户觉得被审问。

#### P — Problem（痛点问题）

> 挖掘客户当前遇到的困难和不满

| 提问模板 | 示例 |
|----------|------|
| "在这个过程中，最让您头疼的是什么？" | "手工录入过程中，最大的困扰是什么？" |
| "有没有遇到过XX问题？" | "有没有遇到过录入错误导致库存差异的情况？" |
| "目前的方式，您觉得效率方面怎么样？" | "每天处理这些单据，耗时大概多久？" |
| "团队对现有流程有什么反馈？" | "录入人员有没有反映工作压力大？" |

#### I — Implication（影响问题）

> 放大痛点的影响，让客户感受到问题的严重性

| 提问模板 | 示例 |
|----------|------|
| "这个问题如果持续下去，会对XX产生什么影响？" | "录入错误如果没有及时发现，会对财务对账造成什么影响？" |
| "因为这个问题，公司大概损失了多少？" | "因为录入延迟，采购周期拉长了多少？影响到生产排期了吗？" |
| "这个问题是否影响到其他部门？" | "单据录入的延迟有没有影响到仓库收货和质检？" |
| "如果旺季来了，这个问题会不会更严重？" | "订单量翻倍的时候，还能靠人手处理吗？" |

#### N — Need-payoff（需求回报问题）

> 引导客户想象问题解决后的美好场景

| 提问模板 | 示例 |
|----------|------|
| "如果能XX，对您来说意味着什么？" | "如果单据识别能自动完成，每月能省下多少人工成本？" |
| "假设这个问题能解决，您最期待的改善是什么？" | "最希望在哪些方面看到提升？准确率还是速度？" |
| "如果效率提升XX%，会对业务产生什么正面影响？" | "如果录入效率提升80%，这些人力可以做什么更有价值的事？" |
| "这样的方案值得您投入多少预算来解决？" | "解决这个问题，您觉得合理的投入范围是多少？" |

### 2.3 客户痛点清单（通用模板）

| 痛点类别 | 常见表现 | 影响程度 | 对应方案 |
|----------|----------|----------|----------|
| **效率低** | 人工操作耗时、流程繁琐、重复劳动 | ★★★★★ | 自动化/系统化 |
| **成本高** | 人力成本高、错误返工成本、机会成本 | ★★★★☆ | 降本增效方案 |
| **错误多** | 人工错误率高、数据不一致、对账困难 | ★★★★☆ | 智能校验 |
| **管理难** | 数据分散、缺乏可视化、决策依据不足 | ★★★☆☆ | 数据集中化 |
| **扩展差** | 业务增长后系统跟不上、瓶颈明显 | ★★★☆☆ | 弹性架构 |

## 第三部分：价值主张与话术模板

### 3.1 FABE法则（特征-优势-利益-证据）

| 要素 | 含义 | 话术结构 |
|------|------|----------|
| **F** (Feature) | 产品/方案的特征 | "我们的方案具备XX功能..." |
| **A** (Advantage) | 相比竞品/现状的优势 | "与传统方式相比，它能..." |
| **B** (Benefit) | 给客户带来的具体利益 | "这意味着您可以..." |
| **E** (Evidence) | 证明以上说法的证据 | "XX客户使用后..." |

#### FABE话术示例

> **F**："我们的OCR智能识别系统支持混合识别——机打、手写、表格都能处理，一次可批量识别50个文件。"
>
> **A**："与人工录入相比，识别速度提升20倍，且支持自动匹配供应商和字段映射，无需二次处理。"
>
> **B**："这意味着您的6人录入团队可以缩减为1人复核，每月节省约3万元人力成本，且数据准确率从92%提升到99%以上。"
>
> **E**："我们在XX行业已有30多家客户，比如A公司上线后，月均处理2万张单据，人工审核率降到了8%，当月就收回了投入成本。"

### 3.2 电梯话术（30秒版本）

```
我们是做________________________的（定位）。

很多____________________行业的公司都面临______________的问题（痛点）。

我们的解决方案可以帮助他们____________________________（价值）。

与市面上其他方案不同的是，我们____________________________（差异化）。

目前已有____家客户在使用，平均带来了________%的____改善（证据）。
```

### 3.3 不同角色的沟通策略

| 角色 | 关注点 | 沟通重点 | 话术要点 |
|------|--------|----------|----------|
| **老板/总经理** | ROI、战略价值、竞争优势 | 投资回报、行业趋势、标杆案例 | "帮您省钱/赚钱/降风险" |
| **业务负责人** | 效率提升、团队管理、KPI达成 | 操作便捷性、可量化效果 | "让您的团队更高效" |
| **IT负责人** | 技术可行性、集成难度、安全性 | 架构方案、接口文档、部署方式 | "技术可靠、集成简单" |
| **财务负责人** | 成本控制、合规性、审计留痕 | 成本对比、数据安全、操作记录 | "合规、可追溯、省成本" |
| **一线使用者** | 好不好用、学不学得会、会不会被替代 | 操作演示、培训支持、人机协作 | "让您的工作更轻松" |

#### 开场白话术

| 场景 | 话术 |

| 场景 | 话术 |
|------|------|

## 第四部分：异议处理手册

### 4.1 LSCPA异议处理模型

```
L — Listen (倾听)   → 认真听完客户的异议，不打断
S — Share  (认同)   → 表示理解客户的顾虑
C — Clarify(澄清)   → 确认真正的异议点是什么
P — Present(解决)   → 针对性地给出回应
A — Ask    (确认)   → 确认客户的疑虑是否已消除
```

### 4.2 常见异议与应对话术

#### 异议一："价格太贵了"

| 步骤 | 应对 |
|------|------|
| **L 倾听** | （点头，认真记录） |
| **S 认同** | "理解您对成本的关注，采购决策确实要慎重考虑投入产出。" |
| **C 澄清** | "您说的贵，是跟您的预算相比，还是跟市面上的其他方案相比？" |
| **P 解决** | "我们来算一笔账：目前6个录入员，月成本3万，一年36万。我们的方案年费XX万，上线后释放4个人力，一年节省24万。也就是说，第一年就能净回报XX万。" |
| **A 确认** | "这样算下来，您觉得这个投入是否合理？" |

#### 异议二："我们考虑考虑"

| 步骤 | 应对 |
|------|------|
| **L 倾听** | （不急于追问） |
| **S 认同** | "当然，这是一个重要的决策，确实需要充分考虑。" |
| **C 澄清** | "方便了解一下，您主要还在考虑哪些方面呢？是方案本身，还是预算，还是需要跟其他同事商量？" |
| **P 解决** | （根据具体顾虑给出针对性回应）"如果是想让其他同事也了解一下，我可以安排一次专门的演示会。" |
| **A 确认** | "我这边先给您准备一份详细的方案资料，您看我们约下周三再碰一下？" |

#### 异议三："我们已经有类似系统了"

| 步骤 | 应对 |
|------|------|
| **L 倾听** | "您现在用的是哪家的方案？" |
| **S 认同** | "有系统意识很好，说明贵公司一直在追求效率提升。" |
| **C 澄清** | "现在这套系统用下来，您觉得哪些方面还有提升空间？" |
| **P 解决** | "我们跟XX系统最大的差异在于……（差异化优势）。很多客户从XX切换过来后，反馈在XX方面有了明显改善。" |
| **A 确认** | "要不我们做个对比演示，您可以直接看看效果差异？" |

#### 异议四："领导还没决定"

| 步骤 | 应对 |
|------|------|
| **L 倾听** | （理解对方不是决策者） |
| **S 认同** | "理解，这样的决策确实需要领导来定。" |
| **C 澄清** | "方便了解一下，领导主要关注哪些方面？我可以帮您准备一份更有针对性的汇报材料。" |
| **P 解决** | "我可以帮您做一份一页纸的ROI分析报告，您拿去汇报会更有说服力。另外如果方便的话，我也可以直接跟领导做个简短交流。" |
| **A 确认** | "您看是先准备材料，还是我直接约个时间跟领导聊？" |

#### 异议五："不着急，以后再说"

| 步骤 | 应对 |
|------|------|
| **L 倾听** | （判断是否为真实异议） |
| **S 认同** | "理解，时机确实很重要。" |
| **C 澄清** | "那您觉得大概什么时候会重新考虑这个事情？有没有一个触发点？" |
| **P 解决** | "我跟您分享一个情况——很多客户一开始也觉得不急，但在旺季来临时发现来不及了。早期介入可以有充分的测试时间。另外我们现在有XX优惠活动。" |
| **A 确认** | "要不这样，我先免费帮您做个现状诊断，出一份分析报告？这样后续不管什么时候启动，都有数据支撑。" |

### 4.3 异议预防清单

| 可预见的异议 | 预防话术（提前在方案中植入） |
|-------------|--------------------------|
| 价格贵 | 在呈现方案时主动做ROI对比，让客户先看到回报再看价格 |
| 技术复杂 | 在方案中强调"3天部署、即开即用"，并展示简洁的操作界面 |
| 数据安全 | 主动介绍安全机制：加密传输、权限隔离、审计日志 |
| 效果不确定 | 提供免费试用/POC验证，用客户自己的数据测试 |
| 团队抵触 | 展示"人机协作"理念，强调是帮助而非替代 |

## 第五部分：报价与谈判策略

### 5.1 报价原则

```
                    ┌─────────────┐
                    │   报价三要素  │
                    └──────┬──────┘
              ┌────────────┼────────────┐
              ▼            ▼            ▼
        ┌──────────┐ ┌──────────┐ ┌──────────┐
        │  价值先行  │ │  锚定效应  │ │  留有余地  │
        │          │ │          │ │          │
        │ 先讲价值  │ │ 先报高套餐 │ │ 预留5-15% │
        │ 再报价格  │ │ 再推荐中档 │ │ 谈判空间   │
        └──────────┘ └──────────┘ └──────────┘
```

### 5.2 报价策略

| 策略 | 适用场景 | 操作方式 |
|------|----------|----------|
| **三级报价法** | 客户预算不明确 | 提供高/中/低三档方案，引导中间档 |
| **拆分报价法** | 总价看起来很高 | 按月/按天/按单拆分成小金额 |
| **对比报价法** | 强调性价比 | 与人工成本/竞品价格做直接对比 |
| **限时优惠法** | 促成快速决策 | 在有效期内签约享受特别价格 |
| **增值赠送法** | 客户砍价幅度大 | 价格不变，额外赠送服务/时长 |

### 5.3 谈判技巧

| 技巧 | 说明 | 示例 |
|------|------|------|
| **绝不接受第一次报价** | 客户砍价时不要立即让步 | "这个价格已经是我们给到的最优方案了" |
| **交换而非让步** | 每一次让步都要换取对方的承诺 | "如果能一次签两年，我可以给您额外优惠5%" |
| **红脸白脸** | 需要请示上级来给折扣 | "我帮您去跟领导申请一下，但不保证能通过" |
| **最后通牒** | 设定截止时间 | "这个优惠价格只保留到本月底" |
| **拆包谈判** | 把大的争议拆成小议题逐个解决 | "我们先把方案范围定下来，价格的事分开讨论" |
